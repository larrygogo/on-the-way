# 项目架构文档

## 概述

本项目采用分层架构设计，从 MVP 系统重构为可持续、可扩展的生产级架构。

## 架构分层

### 1. 核心系统层 (Core Layer)

位置：`src/core/`

核心系统层提供基础设施和通用功能，包括：

#### 事件系统 (`core/events/`)
- **EventEmitter.ts** - 事件发射器基类，提供类型安全的事件订阅和发布
- **GameEvents.ts** - 游戏事件类型定义，包含所有游戏事件接口
- **EventBus.ts** - 全局事件总线（单例），用于系统间解耦通信

#### 资源管理 (`core/resources/`)
- **ResourceManager.ts** - 资源管理器，统一管理资源加载、缓存和释放
- **ResourceLoader.ts** - 资源加载器接口
- **JsonResourceLoader.ts** - JSON 资源加载器实现
- **ImageResourceLoader.ts** - 图片资源加载器（预留）

#### 配置管理 (`core/config/`)
- **ConfigManager.ts** - 配置管理器，支持加载、保存和热重载
- **GameSettings.ts** - 游戏设置类型定义和默认值

#### 服务定位器 (`core/services/`)
- **ServiceLocator.ts** - 服务定位器（单例），提供全局服务访问
- **ServiceContainer.ts** - 服务容器，支持依赖注入和服务生命周期管理

#### 工具函数 (`core/utils/`)
- **ObjectPool.ts** - 对象池，用于重用对象，减少内存分配
- **FrameRateController.ts** - 帧率控制器，控制游戏循环帧率

### 2. 引擎层 (Engine Layer)

位置：`src/engine/`

引擎层提供底层系统功能：

#### 渲染系统 (`engine/render/`)
- **Renderer.ts** - 渲染器，管理 Canvas 上下文和 DPR 自适应
- **Camera.ts** - 相机系统，横向卷轴跟随
- **GroundBand.ts** - 地面带渲染
- **Renderable.ts** - 可渲染接口
- **FrustumCuller.ts** - 视锥剔除器，优化渲染性能

#### 物理系统 (`engine/physics/`)
- **Collision.ts** - 碰撞检测工具（AABB、多边形）
- **SpatialHash.ts** - 空间哈希表，优化碰撞检测性能

#### 输入系统 (`engine/input/`)
- **InputManager.ts** - 输入管理器，统一管理键盘、鼠标和触摸输入，支持输入映射

### 3. 内容层 (Content Layer)

位置：`src/content/`

内容层管理游戏数据和配置：

#### 配置 (`content/config/`)
- **DungeonConfig.ts** - 秘境配置类型
- **MapConfig.ts** - 地图配置类型
- **GameConfig.ts** - 游戏配置常量
- **PortalTemplate.ts** - 传送门模板类型

#### 加载器 (`content/loaders/`)
- **DungeonLoader.ts** - 秘境配置加载器
- **MapLoader.ts** - 地图配置加载器
- **PortalTemplateLoader.ts** - 传送门模板加载器

#### 构建器 (`content/builders/`)
- **WorldBuilder.ts** - 世界构建器，从配置生成游戏世界
- **PortalSpawner.ts** - 传送门生成器

#### 运行时 (`content/runtime/`)
- **MapSwitcher.ts** - 地图切换器

## 核心设计模式

### 1. 单例模式
- EventBus、ResourceManager、ConfigManager、ServiceLocator 等核心服务使用单例模式

### 2. 服务定位器模式
- 通过 ServiceLocator 提供全局服务访问，支持依赖注入

### 3. 事件驱动架构
- 使用 EventBus 实现系统间解耦通信
- 所有重要状态变化和操作都通过事件通知

### 4. 组合模式
- Game 类拆分为多个管理器（GameSession、GameWorld、GameLoop、GameSystems）
- 使用组合而非继承，降低耦合度

### 5. 对象池模式
- 使用 ObjectPool 重用对象，减少内存分配和垃圾回收

## 数据流

```
用户输入 → InputManager → Game → GameWorld → Entities
                                    ↓
                                EventBus
                                    ↓
                            UI/Systems/State
```

## 性能优化

### 渲染优化
1. **视锥剔除** - 只渲染屏幕内的对象
2. **优化排序** - 小数组使用插入排序，大数组使用快速排序
3. **对象池** - 重用对象，减少内存分配

### 碰撞优化
1. **空间哈希** - 使用 SpatialHash 优化碰撞检测
2. **AABB 碰撞** - 使用轴对齐包围盒进行快速碰撞检测

### 资源优化
1. **资源缓存** - ResourceManager 提供资源缓存机制
2. **资源预加载** - 支持批量预加载资源

### 帧率控制
1. **FrameRateController** - 控制游戏循环帧率，避免过度渲染

## 扩展指南

### 添加新系统
1. 在相应的层级创建新文件
2. 实现必要的接口
3. 在 ServiceLocator 中注册服务
4. 通过 EventBus 与其他系统通信

### 添加新事件
1. 在 `GameEvents.ts` 中定义事件类型
2. 在 `GameEventMap` 中添加事件映射
3. 在相应系统中发送事件

### 添加新资源类型
1. 实现 `ResourceLoader` 接口
2. 在 `ResourceManager` 中注册加载器

## 最佳实践

1. **使用事件系统** - 系统间通信优先使用 EventBus
2. **服务定位** - 通过 ServiceLocator 获取服务，而非直接实例化
3. **类型安全** - 充分利用 TypeScript 类型系统
4. **错误处理** - 统一错误处理机制
5. **性能考虑** - 使用对象池、空间哈希等优化技术
6. **代码复用** - 提取公共逻辑到工具函数或基类

## 迁移策略

项目采用渐进式迁移策略：
1. 新系统与旧系统并行运行
2. 逐步迁移功能到新系统
3. 移除旧系统
