## 核心功能说明

### 一、灵气 Aura
- **初始值**: `current = 0`
- **上限**: `cap = 200`
- **HUD 显示**: 常驻显示：灵气 current/cap
- **函数**:
  - `addAura(amount)`: clamp 到 cap
  - `canSpendAura(cost)`: 检查是否可以消耗
  - `spendAura(cost)`: 消耗灵气

### 二、灵气点 AuraNode（地图对象）
- **数据结构**:
  - `id`: 唯一标识
  - `pos(x,y)`: 世界坐标
  - `collectSeconds = 2.0`: 采集读条时间
  - `gainAmount = 20`: 获得灵气数量
  - `radius = 28`: 交互范围
- **渲染**:
  - 扁平风格"能量点"占位（蓝色渐变球体）
  - 玩家靠近时高亮/描边（黄色）
- **交互**:
  - 玩家在 GAME 模式且不在其他读条时，靠近 AuraNode 显示提示：按 E 采集灵气(+20)
  - 按 E 开始采集读条 2s
  - 读条期间进入 `uiMode = "CHANNELING"`
    - 禁用移动/拾取/打开背包等输入
    - HUD 显示读条条（显示"采集中 进度%"）
  - 读条结束：`addAura(20)`，结束 CHANNELING 回到 GAME
  - 采集可被打断（按 Esc 或调用 `cancelChannel()`），打断不获得灵气

### 三、普通区 -> 安全区（带消耗与读条）
- **前置条件**:
  - 安全区剩余容量足够放下该物品（按 size 计算 used+size <= cap）
  - `aura.current >= 8`
  - 当前 `uiMode` 必须是 INVENTORY（从背包里操作）
- **点击"移入安全区"**:
  - 不要立刻扣灵气
  - 开始 CHANNELING，持续 1.5s，显示读条（可复用同一套 Channeling UI）
  - 读条结束后：
    - `spendAura(8)`
    - 将物品从 unsafe 数组移入 safe 数组
    - 若结束时容量/灵气不满足（极少见，但仍要防御），则取消并提示
  - 被打断：不扣灵气、不转移
- **CHANNELING 时**:
  - 禁用再次点击按钮，禁用关闭背包/其他交互（或统一锁输入）
  - 允许 Esc 取消

### 四、状态机与输入冲突
- **uiMode 增加 "CHANNELING"**:
  - `GAME`: 正常移动/拾取
  - `INVENTORY`: 只允许背包 UI 操作
  - `CHANNELING`: 只允许取消（Esc）和渲染读条
- **E 键**:
  - `GAME`: 用于拾取/采集（优先采集 AuraNode，其次拾取 GroundLoot）
  - `INVENTORY`: 不处理 E
  - `CHANNELING`: 不处理 E

## 按键说明

- **E**: 采集灵气点（优先）或拾取物品
- **Esc**: 取消读条（CHANNELING 模式下）
- **I/Tab**: 打开/关闭背包
- **鼠标点击**: 在背包面板中点击按钮进行操作

## 注意事项

- 灵气点采集和普通->安全移动都使用读条系统
- CHANNELING 模式下禁用所有游戏操作
- E 键优先级：AuraNode > GroundLoot
- 普通->安全移动需要 8 灵气，读条 1.5 秒
